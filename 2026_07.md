# 1. Project Overview

Formula SAE telemetry system with real-time simulation, multi-lap race generation, Streamlit dashboard, driver analysis, live coaching recommendations, and F1 real-telemetry integration.

**Key capabilities:**
- Real-time vehicle physics simulation (10 Hz)
- Multi-lap batch simulation
- 19-page Streamlit dashboard for live telemetry, replay, lap analysis, track design, driver profiling
- ML-based recommendation engine (RandomForest segment policies)
- Live coaching assistant with per-segment feedback
- FastF1/OpenF1 integration for real F1 telemetry
- Physics calibration pipeline against real data
- **Tire degradation model** (wear, temperature, graining, blistering, 5 compounds)
- **Fuel consumption model** (mass-varying dynamics over stint)
- **Aerodynamic downforce** (grip enhancement at speed)
- **Adaptive driver model** (fatigue, learning, braking consistency, reaction time)
- **ML residual correction** (XGBoost/RF learns physics error vs real telemetry)
- **Comprehensive validation** (braking points, corner speeds, line deviation, confidence intervals)
- **Optimal lap time simulator** (track analysis → friction-limited corner speeds → predicted best lap)

# 6. Physics Model (Simple)

## Longitudinal Dynamics

```
drag            = 0.5 * ρ * Cd * A * v²
rolling_resist  = Crr * m * g
engine_force    = F_max_engine * throttle
brake_force     = F_max_brake * brake
net_force       = engine - brake - drag - rolling
acceleration    = net_force / m
v_new           = max(0, v + a * dt)
```

## Yaw Dynamics

```
sensitivity = 30.0 / max(speed_kmh / 40.0, 1.0)   # deg/s
yaw_rate    = steering * sensitivity
```

## Thermal Model

```
heat_gen  = throttle * 0.8
speed_heat = speed_kmh * 0.01
cooling   = 0.08 * (speed_kmh / 40.0)
temp_new  = temp + (heat_gen + speed_heat - cooling) * dt * 10
```

## Track Following (GPSMock)

Points move along a closed loop of (x,y) waypoints. Distance traveled interpolates between waypoints. Lap completion detected when within `lap_threshold=2.0` units of start point, with cooldown to prevent double-counting.

# 7. Tire Degradation Model

Tracked per-corner (simplified to single model). State: wear (0..1), surface temp, core temp.

## Compounds

| Compound | Base Grip | Wear Rate | Opt Temp (°C) | Temp Window |
|----------|-----------|-----------|---------------|-------------|
| Soft     | 1.10      | 0.012/km  | 85            | ±15         |
| Medium   | 1.00      | 0.008/km  | 90            | ±20         |
| Hard     | 0.90      | 0.005/km  | 95            | ±25         |
| Inter    | 0.85      | 0.006/km  | 70            | ±20         |
| Wet      | 0.70      | 0.004/km  | 60            | ±15         |

## Grip Model

```
grip = base_grip * (1 - 0.6 * wear) * temp_factor

temp_factor:
  if |surface_temp - opt_temp| <= window: 1.0
  else: max(0.6, 1.0 - (|diff| - window) / 40)
```

## Per-Step Update

```
wear_increment = wear_rate * distance_km * (1 + |throttle| + |brake| + |lat_accel|/10)
surface_temp += (friction_heat + ambient_cooling + conduction) * dt * 10
core_temp    += (conduction_from_surface) * dt * 10
graining     = |surface - core| > 30°C
blistering   = surface_temp > 120°C
```

## API

```python
tire = TireModel(compound="medium")
tire.step(speed_kmh, throttle, brake, lateral_accel, dt)
tire.grip_coefficient  # current grip multiplier
tire.get_state()       # {compound, wear_pct, surface_temp_c, grip, graining, blistering}
tire.reset(compound="soft")  # new set of tires
```

# 8. Fuel Load Model

## Behavior

- Fuel mass starts at `fuel_initial_kg` (default 80 kg)
- Consumption proportional to throttle: `flow = rate * throttle * dt`
- Total vehicle mass = base_mass + fuel_mass → affects acceleration
- Over a stint mass decreases, improving performance

## API

```python
fuel = FuelModel(initial_fuel_kg=80.0, consumption_rate=0.5)
fuel.step(throttle, dt)
fuel.fuel_load_kg
fuel.fuel_pct
fuel.refuel()  # refill to max
```

# 9. Aerodynamic Downforce Model

Extends the simple drag-only model with downforce that increases cornering grip at speed.

## Forces

```
drag      = 0.5 * ρ * Cd * A * v²
downforce = 0.5 * ρ * Cl * A * v²    (Cl = downforce coeff)

Effective grip multiplier:
  (m * g + downforce) / (m * g)      # >1.0 at speed
```

## Maximum Corner Speed (with downforce)

```
v_max = sqrt(μ * m * g / (m/r - 0.5 * μ * ρ * Cl * A))

When downforce term > mass/radius term → no speed limit (aerodynamic cars)
```

## API

```python
from simulator.physics.simple.aero import AeroModel
aero = AeroModel(downforce_coeff=1.2, aero_balance=0.5)
drag_force = aero.compute_drag(v_ms)
df_force = aero.compute_downforce(v_ms)
grip_mult = aero.effective_grip_multiplier(v_ms, mass_kg)
v_max = aero.max_corner_speed(radius, mu, mass_kg)
```

# 10. Sensor Models

All current sensors take a `true` value and return a noisy reading with optional dropout.

| Sensor | Input | Output | Noise | Dropout |
|--------|-------|--------|-------|---------|
| `WheelSpeedSensor` | true speed (km/h) | noisy speed (km/h) | Gaussian(std) | None on dropout |
| `BrakePressureSensor` | true brake_cmd * 100 | pressure (bar) | Gaussian(std) | None on dropout |
| `CoolantTempSensor` | true temp (°C) | noisy temp (°C) | Gaussian(std) | None on dropout |
| `IMUSensor` | true_ax, true_ay, true_yaw | {ax, ay, yaw} | Per-axis Gaussian(std) | None on dropout |

Noise models: `gaussian_noise(mu=0, sigma)`, `occasional_dropout(prob)`.

Legacy sensors (`simulator/sensors/`) use hardcoded sine waves and random events — kept for backward compatibility.

# 12. Adaptive Driver Model

Extends the simple `DriverProfile` with dynamic behavior over a stint.

## Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `throttle_bias` | 1.0 | Base throttle tendency |
| `aggressiveness` | 0.2 | Late braking / early throttle |
| `steering_noise` | 0.02 | Steering variability |
| `braking_consistency` | 0.9 | 1.0 = perfect braking point (low variance) |
| `corner_aggressiveness` | 0.5 | How late they brake into corners |
| `racing_line_preference` | middle | inside / middle / outside |
| `reaction_time` | 0.15 s | Delay in control changes |
| `fatigue_rate` | 0.02 / lap | Performance degradation per lap |
| `learning_rate` | 0.01 / lap | Improvement per lap |

## Dynamic State

- `fatigue` (0..1): increases each lap, reduces effective aggressiveness and consistency
- `confidence` (0..1): increases when lap times are near target, reduces steering noise
- `consecutive_laps`: affects fatigue accumulation

## API

```python
driver = AdaptiveDriver(driver_id="adaptive_expert", braking_consistency=0.98,
                        corner_aggressiveness=0.6, reaction_time=0.08)
throttle, brake, steering = driver.get_action(t, lap_time, curvature, speed_kmh)
driver.on_lap_complete(lap_time, target_time)  # updates fatigue + confidence
driver.reset_stint()
driver.get_state()  # {fatigue, confidence, effective_* params}
```

# 15. ML Residual Correction

Learns the error between physics simulation and real telemetry, then corrects future predictions.

## Pipeline

```
logs/*.json
  → extract_features(speed, throttle, brake, yaw, curvature, tire, fuel, aero)
  → run physics with same controls
  → target = real_speed - physics_speed (the residual)
  → train XGBoost / RandomForest / MLP
  → predict correction: corrected_speed = physics_speed + prediction
```

## Supported Models

| Model | Library | Performance |
|-------|---------|-------------|
| XGBoostRegressor | xgboost | Best (default) |
| RandomForestRegressor | sklearn | Good fallback |
| MLPRegressor | sklearn | Neural network option |

## Training

```bash
# Train on all session logs
python simulator/residual_model.py --log-dir data/logs/ --model-type auto

# Train with specific model
python simulator/residual_model.py --model-type xgboost --save-path data/models/residual.pkl
```

## API

```python
model = ResidualModel(model_type="xgboost")
features, targets = model.build_training_data(real_packets)
metrics = model.train(features, targets)
# metrics: {train_r2, test_r2, mae_kmh, rmse_kmh}

# At inference:
correction = model.predict(feature_vector)
corrected_speed = physics_speed + correction[0]

model.save("data/models/residual.pkl")
model.load("data/models/residual.pkl")
```

# 17. Physics Calibration

## `simulator/calibrate_from_f1.py`

Tunes car parameters against real F1 speed traces using scipy optimization.

**Pipeline**:
1. Load real lap data (converted via FastF1/OpenF1)
2. Run FSAE physics with real throttle/brake traces
3. Compute speed RMSE between simulated and real
4. Optimize 6 parameters with L-BFGS-B:

| Parameter | Bounds | Default |
|-----------|--------|---------|
| `mass` | 150-400 kg | 210 |
| `drag_coeff` | 0.3-1.5 | 0.9 |
| `frontal_area` | 0.5-2.0 m² | 1.0 |
| `rolling_resistance` | 0.005-0.04 | 0.015 |
| `max_engine_force` | 3000-12000 N | 6000 |
| `max_brake_force` | 500-3000 N | 1500 |

5. Save calibrated params to `car_simple_calibrated.yaml` or apply to live config
6. Generate per-lap validation report (MAE/RMSE/sector errors)

**CLI**:
```bash
python simulator/calibrate_from_f1.py --lap-file data/logs/f1_VER_*.json --calibrate --report
python simulator/calibrate_from_f1.py --lap-file data/logs/f1_VER_*.json --eval
python simulator/calibrate_from_f1.py --lap-file data/logs/f1_VER_*.json --calibrate --apply
```

# 19. Lap Time Simulator

Computes theoretical optimal lap time from track geometry and vehicle limits — without running a full simulation.

## Approach

```
Track waypoints
  → compute curvature at each point
  → detect corners (radius, arc length) and straights
  → compute max corner speed from friction circle + downforce
  → compute acceleration on straights (full throttle with drag)
  → compute optimal braking distances
  → assemble predicted lap time
```

## Key Computation

Maximum corner speed with downforce:
```
v_max = sqrt(μ * m * g / (m/r - 0.5 * μ * ρ * Cl * A))

where Cl = downforce coefficient, r = corner radius
```

## Usage

```bash
# Analyze oval track
python simulator/lap_time_simulator.py --track-type oval --mu 1.2

# Analyze CSV track with comparison
python simulator/lap_time_simulator.py \
  --track data/tracks/default_track.csv \
  --downforce 1.4 \
```

# 24. Error Handling & Edge Cases

- **Sensor dropout**: All sensors return `None` on dropout. Dashboard handles `None` values gracefully.
- **JSON atomic writes**: `atomic_write()` uses tmp-file + os.replace with retry fallback.
- **Stop signal**: Simulator checks `data/stop_signal.txt` for graceful exit.
- **Missing track files**: Falls back to oval track.
- **No session logs**: Recommender falls back to heuristic profiles.
- **FastF1 not installed**: Functions return `None`, print install instructions.
- **OpenF1 rate limit**: ~250 req/hr; `OpenF1Stream` polls at 0.5s intervals.
- **Calibration failure**: L-BFGS-B may fail to converge; prints error, returns current best.
- **No ML libraries**: Residual model falls back to zero correction if xgboost/sklearn unavailable.
- **Tire overheat**: Surface temp clipped to 140°C, blistering flag set.
- **Fuel empty**: Fuel model returns 0 kg, no further consumption.
- **Empty track**: Lap time simulator returns 0 if track has no points.
